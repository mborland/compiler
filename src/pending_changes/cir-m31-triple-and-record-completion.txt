CIR back end: target triple capture and record completion hook

In the CIR back end configuration (BACK_END_TYPE_CIR), and only in it, the
target triple of the ECIL stream is now captured right after the predefined
macros are entered (a new call in the translation unit initialization of
fe_init.c), so that a source file that undefines the system macros of the
target (#undef __linux__) cannot change it; before, it was read from the macro
table when the stream's header was written.  The class definition scanner
(class_decl.c, complete_class_definition) now tells the ECIL writer when a
class is complete, so that the writer looks again at the records it declared
as incomplete only then, not at the end of every function.  The reason that
the ECIL writer gives for a dropped function or variable is no longer cut
after 100 characters and is also sent with the unsupported declaration to the
CIR library (ECIL 1.1).  The other configurations are not affected.
