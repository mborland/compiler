**Before coding L1 to L3: measure and propose** (one report, then advisor call point 2). No limit is chosen from
a guess:
- the largest `index + repeat` and the largest expanded element count of any `C_REPEAT` in the C and C++ corpus
  streams and the stress generators;
- the deepest bracket nesting the writer emits for the stress steps (the 20,000-rung else-if ladder, the nested-if
  kinds of `ecil-stress-gen.py`) and the corpus;
- where the 300 s of the SEC-1-5 reproducer go: `ecil-dump` (validator only) against `edg-cir`. The four stack
  walks in `ecil_brackets.cpp` that run from the function base to the top are the suspects;
- which alignment, bit-width and zero-initializer values the writer really sends (0 is a legal "default" in
  several places; C++ allows a bit-field wider than its type).

- **L1. SEC-1-3 (High): unbounded `C_REPEAT` expansion.** Today `globals.cpp` expands with
  `elements.assign(listed, …)` in two places (the member-pointer array path and the plain array path), and the
  validator's `check_selector` bounds `index + repeat` by the array extent only when the type has a count.
  Fix both sides:
  - validator: `index + repeat` is bounded for every array, and there is an absolute bound on what one constant
    may expand to (a reader option beside `max_frame`; the default from the measurement, with headroom);
  - emitter: memory proportional to the stream, not to the array count. Use the trailing-zeros form
    `string_attribute` already uses (a `ConstArrayAttr` shorter than the array) wherever the tail is zero, and
    diagnose the rest above the bound.
  A legitimately huge initializer is out of scope (`security.md` §1); a 134-byte stream asking for 8 TiB is not.
- **L2. SEC-1-4 (High): unchecked layout numbers.** Validator checks in `ecil_refs.cpp`, each matching what the
  consumer assumes:
  - `LOCAL` and `DECL_VAR` alignment (0 or a power of two, within LLVM's maximum); `TY_RECORD_BODY` alignment
    (the model is the `CLASS_INFO` nvalign check in `ecil_classes.cpp`; share its `is_power_of_two`);
  - `REC_FIELD` bit width (bounded so that `types.cpp`'s 32-bit truncation cannot wrap);
  - `need_object` rejects function and `void` types for `LOCAL`, `PARAM` and `MATERIALIZE_TEMP` (only `DECL_VAR`
    rejects them today);
  - `C_ZERO` and `INIT_ZERO` only on types that have a zero value.
  Exit: none of the SEC-1-4 inputs reaches an LLVM or MLIR assertion; each is a format error.
- **L3. SEC-1-5 (High): no depth limit.** If the measurement shows the validator's own walks are quadratic, fix
  the walks (cached counters) first. Then add a depth limit as a format error (a reader option; the constant
  lives beside `id_slack` or in `a_reader_options`), and cap the validator's other stacks (`fns_`,
  `agg_targets_`, `const_targets_`) the same way. The limit must clear the deepest legitimate stream by a wide
  margin; if any corpus or stress stream comes near the candidate, stop and report.
- **L4. Lows, if cheap** (else they stay open): SEC-1-7, a name id 0 is treated the same by the validator
