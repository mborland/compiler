## 2. Known gaps (each diagnosed)

| Gap | Why | Where / test |
| --- | --- | --- |
| A return-adjusting thunk of a variadic function | CIRGen has the same gap (no way to forward the variable arguments and adjust the result) | `classes.cpp` "unsupported"; no lit test |
| A union with reusable tail padding as a base or `[[no_unique_address]]` member | the CIR record for it is not defined | `types.cpp`; no lit test |
| Lambdas and other nested function bodies | not designed (ECIL streams every body at top level) | `function.cpp` unsupported; no lit test |
| A bit-field glvalue carried out of a full expression | no CIR value for it | `function.cpp` unsupported; no lit test |
| A `switch` on a 128-bit integer with a negative or wider-than-64-bit label | the MLIR LLVM switch translation reads case values as unsigned 64 bits | `int128-switch-unsupported.test` |
| C++ records in an ECIL v1 context, and any record or flag newer than the stream minor | contract versioning | `v1-record-unsupported.test`, `bad_v10_*`/`bad_v11_*` fixtures |
| An array whose element destructor may throw: the elements before the throwing one are not destroyed (the writer diagnoses it; the library does not set `dtor_may_throw` on `cir.array.dtor`) | with the property the pin's FlattenCFG asserts ("cleanup region has exits in non-final blocks") | `cxx-s4-eh-cleanup-throw` (arr_elem: element 0 only, which matches g++) |
| `C_METHOD` with a non-zero adjustment in a function body | `#cir.method` cannot hold it (G2); the writer uses `CONST_METHOD` | `bad-cxx-*` / format rule |
| Non-x86-64 triples, Microsoft ABI, relative vtables | not designed | "unsupported target" error |
| Null of a union: the first member is taken by CIR member order, not "first named" | an unnamed first member without named data members is not handled | `cxx-s4-union-null-member-pointer` (the normal case) |
| A destroying operator delete chosen by a new-expression, GNU statement expressions inside expressions, a throw-operand nested block | the contract cannot express them (writer diagnoses; the reader rejects BLOCK inside a FULLEXPR) | format rule |

Not gaps but limits: no local patches to the LLVM pin; G2 lowered form is
per variable (a method pointer with an adjustment makes its whole variable
lowered).

Numbers are `m4_stress.md` (box, `ulimit -s 256`; growth per doubling in
parentheses).  Ours (decode, emit, finish) is linear except vtable layout,
whose cubic term is inherent in clang's algorithm.

| Item | Numbers | Owner |
| --- | --- | --- |
| lowering of a vtable with N virtual functions | 10000 functions 1.2 s (3.9x) | upstream (quadratic) |
| lowering of a lattice of virtual bases | diamond 160 layers (320 classes) 31.5 s, 4.2 GB | upstream |
| lowering/verify of N cleanups pending (`new` in one expression, unwind through N locals) | news 2500: 17 s lowering (cubic); unwind 4000: 20 s, equal to clang -fclangir (18 s) | upstream |
| CIRCanonicalize on nested try | 500/1000/2000 nested try: 1.5/13.8/208 s (9-15x) | upstream (`findCommonAncestor`); unrealistic input |
| override chain (vtable layout) | 500/1000/2000 levels: 0.5/3.6/26 s finish (7.5x) | ours, inherent in the algorithm (a 400-level chain is 0.2 s); guarded by abi_tests |
| verifier on `new` chains | news 2500: 1.75 s | upstream |

Pin bugs and gaps the library works around (G1 to G8 are in
`research/m4_cir_shapes.md` section 5):

- G1 no `__cxa_free_exception` cleanup in CIRGen: ours, lazily.
- G2 `#cir.method` has no this-adjustment: lowered `{i64, i64}` global form,
  or run-time `derived_method` in a function.
- G3 clang runs cleanups before terminate in `noexcept`: followed.
- G4 `.base` is `nvsize`: `CLASS_INFO.nvsize` is required.
- G5 the text printer prints location aliases it does not define: not used.
- G6 NYI: delegating constructor call, `__fundamental_type_info` vtables,
  relative vtables, MS deleting-destructor flag: the library builds the VTT
  arguments and D0 itself.
- G7 conditional `new` with temporaries: CIRGen frees before destroying the
  temporaries, g++ and classic clang the other way: ours follows g++.
- G8 null of a data-member pointer is -1: expanded constants.
- CXXABI lowering reads the initial value of a pointer-to-member global
  without a null check, so an extern declaration crashes it: the pipeline
  gives each such declaration a null initializer for the CIR passes and takes
  it away again (`cxx-s4-member-pointer-decls`).
- FlattenCFG cleanup rules: a cleanup scope body needs an exit (the dead
  block that holds the yield is kept when every path ends in `unreachable`,
  `terminate_region`); a cleanup region may not contain a nested EH scope with
  exits in non-final blocks (hence no `dtor_may_throw` on array.dtor); a
  `noreturn` call at the end of a cleanup body is marked `noreturn` and emission
  continues; a ctor region needs an initial value (partial static init).
- Dead-block rule: empty blocks no predecessor reaches are erased (CIRGen's
  `terminateStructuredRegionBody`), except the one above.
- EHABILowering: catch copy thunks must be single-block (ours are);
  `catch` by reference to pointer binds a temporary copy (documented departure).
- CallConvLowering has no `cir.try_call`: not reached (it runs before
  FlattenCFG).
- Pin deviations found by the shape differential
  (`m4_cir_differential.md`): D0 is a trap stub or wrapped in try/terminate;
  no vptr store in destructors; conditional `new` frees before the
  temporaries; no `*` prefix for internal-linkage typeinfo names;
  `emitNewArrayInitializer`, function-try-block destructors, global delete of
  a polymorphic object and `emitNullBaseClassInitialization` are NYI.

What an LLVM bump should retest: the whole lit suite and, specifically,
`cxx-s4-member-pointer-decls` (the guard), `cxx-s3-spike-method_const_adj` and
`cxx-s4-method-pointer-lowered-aggregates` (does `#cir.method` gain an
adjustment), every `cxx-s4-eh-*` and `cxx-s4-delete-array-throw` (FlattenCFG,
EHABILowering), `arr_elem` of `cxx-s4-eh-cleanup-throw` (`dtor_may_throw` could
then be set), the thunk tests, `cxx-s4-stress-diamond` and the stress table,
and `box_diff_m4.sh` (deviations that close: D0 stubs, destructor vptr,
conditional new order).  `CIRCompat.h` is the only file that names upstream
API; a bump shows up there first.  `research/m4_upstream_drift.md`: 264
commits after the pin, none fixes a known gap.

## 4. Clang-consistent differences from g++

The rule (user, 2026-10-12): follow clang where clang and g++ differ on an
ABI- or behavior-visible detail.  Exceptions: object layout is the FE's
(g++'s "nearly empty" clause), and the typeinfo name of a TU-local type has
g++'s `*` prefix.  What the library does like clang:

- Temporaries of a throw operand are destroyed during unwinding (g++: before
  `__cxa_throw`).
- Cleanups of a `noexcept` function run before `std::terminate` (G3).
- A nothrow `new[]` with a bad size returns null (clang and the FE; g++
  throws): `NEW_ARRAY_SIZE`; the throwing form is `NEW_ARRAY_SIZE_THROW`.
- In an array constructor whose element initialization has a default
  argument temporary whose destructor throws, the element is not destroyed
  (g++ destroys it).
- When a local's destructor throws on the return path, the returned object is
  not destroyed (CWG 2176; g++ destroys it).  Checked with clang 21.1.8 at
  -O0 in C++17, 20 and 23 (no reference to the object's destructor in the
  IR) and with the pin.
- `::delete`'s size operand is the one clang passes; D0 for a destroying
  operator delete calls only the operator.
- An array whose element destructor throws: the elements before it are not
  destroyed (the pin; classic clang and g++ do).  Diagnosed by the writer.
- Null data member pointers are -1 everywhere, also inside the base subobject
  of a zero-initialized object (g++ writes 0 there: interop caveat).
- D1 of a class with virtual bases is "D2, then the virtual bases"
  (equal in behavior to clang's duplicated body, not byte-equal).

Where the library follows g++ and classic clang against the pin's CIRGen: the
order of `~temporary` and `operator delete` for a `new` whose constructor
throws (G7), and the vptr store in destructors.

## 5. Library assumptions on the writer that the validator does not enforce

Not an exhaustive audit.  Everything the reader can check from the stream is
checked (about 280 messages in `lib/format`: brackets, references, class
facts and their consistency with the vtable builder, flag masks and now the
stream minor, `STRUCTOR_DELETING`/`DELETE` shapes).  What is left, by whether
it could be checked:

Cannot be checked from the stream (truthfulness of facts; a wrong value
miscompiles silently):
- `NOTHROW` on `DECL_FUNC` and `CALL`, and `FUNC_EH_SPEC` lists: a wrong
  `NOTHROW` skips cleanups.  The writer takes it from the FE predicates
  only (`is_non_throwing_routine`, `is_nothrow_type`).
- `NONTRIVIAL_ABI` and `NONTRIVIAL_DTOR` on records: they decide how a class
  is passed and returned.
- Class layout, slots, final overriders and the primary base against the
  source (the library recomputes slots and the layout rules from the facts,
  so only inconsistent facts are caught; 7712 of 7716 FE facts agreed with
  clang over 761 classes).
- Linkage, comdat and guard flags of vtables, typeinfo and static locals.

Checked since the first version of this section (validation tightenings that
no correct writer can violate; each has a `bad_v12_*` fixture or a lit test):
- `CATCH_PARAM` kinds 0 and 1 need a pointer-typed parameter, kind 2 a scalar
  (bool, integer, floating, pointer for `nullptr_t`, pointer to data member or
  member function); kinds 4 to 7 were checked already.
- `THROW_END`: its typeinfo is the one of the type of its `THROW_BEGIN` (a
  class by G-id, any other type by kind and width), and it names a destructor
  if and only if the thrown class has a non-trivial destructor
  (`NONTRIVIAL_DTOR` of its `TY_RECORD_BODY`), which must be a member function
  of that class.  For a non-class type the typeinfo is compared by kind and
  width only (the stream has no cv-qualified type ids), so `int` against
  `unsigned` is not caught.
- `ZERO_BYTES`: the library (not the reader, which has no expression types)
  rejects a count that is larger than the glvalue's type and not a whole number
  of its elements (`new T[n]()` zeroes `n` elements through the first one).
  An off-by-one count inside that range is still accepted.

None of these is a known miscompile; each is a silent one if the writer is
wrong.  Nothing else on the could-be-checked list is left.

## 6. Performance

Release-like build (RelWithDebInfo, box), generated 6000-function
translation units of `edg-cir-rss` (stage times in ms, three runs agree to
2%).  M3.1 library (commit 511d7a76fc) against the current one on the same C++
stream (no exceptions, 5105 frames, 155 000 records):

| Stage | M3.1 | now |
| --- | --- | --- |
| decode+validate | 21 | 48 |
| emit | 64 | 80 |
| finish | 7 | 7 |
| verify | 23 | 23 |
| CIR passes | 178 | 178 |
| lower | 585 | 600 |
| codegen | 357 | 359 |
| peak RSS | 154 MB | 152 MB |

The same C++ TU with exceptions on (the default): decode 48, emit 82, passes
184 (+3%), lower 633 (+5%), codegen 438 (+22%), peak RSS 159 MB.  The C
6000-function TU: decode 122 (M3.1 82), emit 258 (233), the rest equal, peak
423 MB (427).  The decode growth is the stricter reader (class facts, bracket
rules, flag masks); the S1 to S4 slices are not separately measurable any more
(they are one reader and one emitter).  A regression found on the way was a
big-stack thread per consume call (25 us each, 135 ms on this TU); a persistent
worker (`a_guard_worker`) removed it (decode was 158 ms, emit 143 ms before).

EH cost (132 corpus files that the FE also accepts with `--no_exceptions`;
`m4_stress.md`): object bytes +3.9%, edg-cir total +4%.

Stress (section 3 and `m4_stress.md`): the library's own stages are linear in
every kind; what is slow at large N is upstream.  The diamond lattice
regression guard is `cxx-s4-stress-diamond` and `abi_tests`.
